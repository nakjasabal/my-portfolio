# 강사 포트폴리오 사이트 기획

## 프로젝트 개요
- 등록 항목: 자기소개, 기술스택, 교안, 인강, 경력, 저서
- 강의 분야: Java, Spring, AI, Big Data, HTML, CSS, JavaScript, Python, Flutter
- 저서 2권 보유
- 데이터 등록용 관리자 모드는 별도 구축 예정 (프론트 설계 시 고려 불필요)
- 백엔드 기술스택 미정

## SPA vs 일반 페이지(MPA)

**결론: MPA 기반(또는 SSG/SSR 하이브리드) 추천, 순수 SPA는 비추천**

이유:
- 소개/기술스택/교안/인강/경력/저서는 대부분 읽기 위주의 정적 콘텐츠라 복잡한 상태 관리나 앱형 페이지 전환이 필요 없음
- 검색 노출(SEO)이 중요함 — 강사 사이트는 검색 유입이 많은데 순수 CSR SPA는 크롤링에 불리함
- 교안·저서 상세 페이지는 개별 URL로 공유·검색되어야 하므로 MPA/SSG 구조가 유리함

다만 완전히 옛날 방식의 풀 리로드형 MPA보다는, **정적 생성 + 필요한 부분만 클라이언트 인터랙션**하는 하이브리드가 요즘 표준.

- **Astro**: 콘텐츠 중심 사이트(블로그, 포트폴리오)에 최적화. 기본은 정적 HTML로 뿌리고 필요한 위젯만 JS 하이드레이션. 백엔드 미정인 지금 단계에서 가장 가볍게 시작하기 좋음.
- **Next.js**: React 기반, SSR/SSG 모두 가능하고 나중에 API Route로 백엔드까지 확장하기 쉬움. 관리자모드나 동적 기능이 늘어날 가능성이 있다면 더 유연한 선택.

## 정리 순서 (7단계)

### 1. 목적과 타겟 정의
이 사이트를 보는 사람이 누구인지(수강생, 학원/기업 담당자, 출판사 등) 정하면 톤앤매너와 강조할 정보(경력 vs 교안 vs 저서)가 달라짐.

### 2. 콘텐츠 인벤토리 작성
소개, 기술스택, 교안, 인강, 경력, 저서 각 항목마다 어떤 데이터 필드가 필요한지 목록화.
- 예: 교안 = 제목 / 대상 기술 / 난이도 / 파일링크 / 썸네일
- 예: 저서 = 표지 / 출간일 / 목차 / 구매링크

이 목록이 나중에 DB 스키마와 관리자모드 입력폼의 기초가 됨.

### 3. 정보구조(사이트맵) 설계
메인 메뉴 구성(예: 소개 / 기술스택 / 교안 / 인강 / 경력 / 저서 / 연락처)과 각 메뉴의 하위 페이지 구조를 정함. 단일 페이지 스크롤형으로 갈지, 메뉴별 개별 페이지로 갈지 이 단계에서 결정.

### 4. 와이어프레임 스케치
각 페이지의 대략적인 레이아웃(헤더, 히어로 영역, 카드 리스트, 상세 페이지 구성)을 손그림이나 Figma 수준으로 러프하게 그려봄.

### 5. 디자인 톤앤매너 결정
강사 브랜딩에 맞는 컬러/폰트/전체 무드를 정함. 다루는 기술이 많으므로(Java~Flutter) 너무 특정 언어 색(예: 파이썬 노랑)에 치우치지 않는 중립적이고 전문적인 톤을 추천.

### 6. 기술스택 선택
콘텐츠 구조가 정해진 뒤에 확정.
- 프론트: Astro / Next.js 등
- 백엔드: 교안·인강 메타데이터를 어디에 저장할지 — Node/Express, Spring Boot, 또는 Headless CMS+API
- DB: 관계형 vs NoSQL

관리자모드에서 CRUD가 잦다면 백엔드는 익숙한 Spring Boot도 좋은 선택.

### 7. 데이터 모델 및 API 설계
인벤토리에서 정리한 필드를 기반으로 각 콘텐츠 타입(교안, 인강, 저서 등)의 스키마와 이를 노출할 API 엔드포인트를 설계.
